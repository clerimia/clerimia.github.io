Pi Agent Session 上下文初始化

发表于2026-07-16|更新于2026-07-15|技术AIpi-agent
|浏览量:

【clerimia：】 之前拆了 AgentLoop 引擎和五个包的领域对象，但一直没搞清楚一个关键问题：pi 启动时到底往 LLM 发了什么？"上下文"到底是个什么东西？这次直接读 pi-coding-agent 的源码，把 session 初始化和 context 组装的过程完整还原。

1. 先看结论：Context 不是扁平的字典

我之前以为 pi 初始化时组装了一个 context = { systemPrompt, AGENTS.md, skills, tools, messages } 这样的扁平对象。读完源码发现不是。

实际结构是三层分离：

发往 LLM 的请求
├── System Prompt（字符串）── 每次 turn 前可能被 extension 覆盖
│   ├── 默认模板 或 SYSTEM.md
│   ├── APPEND_SYSTEM.md
│   ├── <project_context> 包裹的 AGENTS.md 链
│   ├── <available_skills> XML 块
│   ├── "Available tools:" 列表（来自 tool promptSnippet）
│   ├── "Guidelines:" 列表（来自 tool promptGuidelines）
│   └── Current working directory: ...
│
├── Tools（function schema 数组）── Agent state 层，独立于 system prompt
│
└── Messages（消息数组）── 从 JSONL 恢复，独立于 system prompt

关键认知：system prompt 和 messages 是两条独立路径。messages 不进入 system prompt，tools 同时在 system prompt（文本描述）和 Agent state（function definitions）中存在。

2. 形式化表述

2.1 数据结构

Session::=(systemPrompt, basePrompt, tools, messages, model, thinkingLevel)basePrompt=buildSystemPrompt(loader)=Template⊕AGENTS_Files⊕SkillsBlock⊕ToolSnippets⊕ToolGuidelines⊕CWDsystemPrompt∈{basePrompt, extensionOverride}

其中 ⊕ 表示字符串拼接。

2.2 数据操作

-- 初始化
init(ResourceLoader, SessionManager, Settings) → Session

  let basePrompt = buildSystemPrompt(
    customPrompt  = loader.systemPrompt,      -- SYSTEM.md 或默认模板
    append        = loader.appendSystemPrompt, -- APPEND_SYSTEM.md
    contextFiles  = loader.agentsFiles,        -- AGENTS.md 链
    skills        = loader.skills,             -- 来自各 skill 目录
    tools         = defaultTools,              -- [read, bash, edit, write]
    toolSnippets  = toolDefs.snippets,
    toolGuidelines = toolDefs.guidelines,
    cwd           = cwd,
  )

  let messages = sessionManager.buildSessionContext().messages  -- JSONL 恢复

  return Session {
    systemPrompt = basePrompt,
    basePrompt   = basePrompt,
    tools        = activeTools,
    messages     = messages,
    model        = resolveModel(settings, sessionManager),
    thinkingLevel = resolveThinkingLevel(settings, sessionManager),
  }


-- 每轮 turn 前（Agent.prepareNextTurnWithContext）
refreshTurnContext(Session) → (SystemPrompt, [ToolDef], Model, ThinkingLevel)

  return (
    Session.systemPrompt,          -- extension 可覆盖，否则 = basePrompt
    Session.tools.slice(),         -- 浅拷贝
    Session.model,
    Session.thinkingLevel,
  )


-- Extension 覆盖 system prompt（prompt 方法中 before_agent_start 事件）
overridePrompt(Session, newPrompt) → Session

  Session.systemPrompt = newPrompt    -- 仅当轮有效，turn 结束后 reset
  return Session


-- Rebuild（tool 变更 / extension 追加资源时）
rebuild(Session, loader, activeToolNames) → Session

  Session.basePrompt = buildSystemPrompt(...)  -- 重算
  Session.systemPrompt = Session.basePrompt     -- reset
  return Session

2.3 不变量

∀ turn:Session.systemPrompt∈{Session.basePrompt, extensionOverride}∀ turn:after turn_end→Session.systemPrompt=Session.basePrompt∀ rebuild:Session.systemPrompt=Session.basePrompt

3. 源码追踪：从 createAgentSession 到 buildSystemPrompt

3.1 入口：createAgentSession（sdk.js）

// sdk.js - createAgentSession()
export async function createAgentSession(options = {}) {
  // 1. 创建/复用 ResourceLoader
  let resourceLoader = options.resourceLoader;
  if (!resourceLoader) {
    resourceLoader = new DefaultResourceLoader({ cwd, agentDir, settingsManager });
    await resourceLoader.reload();  // ← 从这里加载所有资源
  }

  // 2. 从 SessionManager 恢复历史消息
  const existingSession = sessionManager.buildSessionContext();
  const hasExistingSession = existingSession.messages.length > 0;

  // 3. 解析 model 和 thinkingLevel
  //    - 优先从 session 恢复
  //    - 其次从 settings 默认值
  //    - 最后用 findInitialModel

  // 4. 创建 Agent 实例（初始 systemPrompt 为空字符串）
  agent = new Agent({
    initialState: {
      systemPrompt: "",  // ← 注意：这里传空字符串
      model,
      thinkingLevel,
      tools: [],
    },
    // ...
  });

  // 5. 恢复历史消息
  if (hasExistingSession) {
    agent.state.messages = existingSession.messages;
  }

  // 6. 创建 AgentSession —— 这里才真正构建 system prompt
  const session = new AgentSession({
    agent,
    sessionManager,
    settingsManager,
    cwd,
    resourceLoader,
    // ...
  });
}

【clerimia：】 关键点：createAgentSession 不直接构建 system prompt。它把 resourceLoader 传给 AgentSession，由 AgentSession 的构造函数去构建。

_rebuildSystemPrompt 是真正组装 system prompt 的地方：

_rebuildSystemPrompt(toolNames) {
  // 1. 从 tool registry 收集 promptSnippet 和 promptGuidelines
  const toolSnippets = {};
  const promptGuidelines = [];
  for (const name of validToolNames) {
    toolSnippets[name] = this._toolPromptSnippets.get(name);
    promptGuidelines.push(...this._toolPromptGuidelines.get(name));
  }

  // 2. 从 ResourceLoader 获取 system prompt、skills、context files
  const loaderSystemPrompt = this._resourceLoader.getSystemPrompt();
  const loaderAppendSystemPrompt = this._resourceLoader.getAppendSystemPrompt();
  const loadedSkills = this._resourceLoader.getSkills().skills;
  const loadedContextFiles = this._resourceLoader.getAgentsFiles().agentsFiles;

  // 3. 调用 buildSystemPrompt 组装
  return buildSystemPrompt({
    cwd: this._cwd,
    skills: loadedSkills,
    contextFiles: loadedContextFiles,
    customPrompt: loaderSystemPrompt,
    appendSystemPrompt,
    selectedTools: validToolNames,
    toolSnippets,
    promptGuidelines,
  });
}

3.4 buildSystemPrompt：字符串拼接工厂

// system-prompt.js
export function buildSystemPrompt(options) {
  const { customPrompt, selectedTools, toolSnippets, promptGuidelines,
          appendSystemPrompt, cwd, contextFiles, skills } = options;

  // 如果提供了自定义 prompt（SYSTEM.md），直接用它
  if (customPrompt) {
    let prompt = customPrompt;
    if (appendSystemPrompt) prompt += appendSystemPrompt;
    // 追加 project context（AGENTS.md）
    if (contextFiles.length > 0) {
      prompt += "\n\n<project_context>\n\n";
      for (const { path, content } of contextFiles) {
        prompt += `<project_instructions path="${path}">\n${content}\n</project_instructions>\n\n`;
      }
      prompt += "</project_context>\n";
    }
    // 追加 skills
    if (skills.length > 0) {
      prompt += formatSkillsForPrompt(skills);
    }
    prompt += `\nCurrent working directory: ${cwd}`;
    return prompt;
  }

  // 否则使用默认模板
  // 1. 构建 "Available tools:" 列表（来自 toolSnippets）
  // 2. 构建 "Guidelines:" 列表（来自 promptGuidelines）
  // 3. 拼接默认模板 + append + context files + skills + cwd
}

【clerimia：】 buildSystemPrompt 分两条路径：有 SYSTEM.md 就直接用，没有就用默认模板。无论哪条路径，AGENTS.md、skills、cwd 都是追加的。

4. ResourceLoader：资源从哪里来

DefaultResourceLoader.reload() 是资源发现的核心，按优先级加载：

资源 来源 优先级
System Prompt .pi/SYSTEM.md → ~/.pi/agent/SYSTEM.md → 默认模板 项目 > 全局 > 默认
Append Prompt .pi/APPEND_SYSTEM.md → ~/.pi/agent/APPEND_SYSTEM.md 项目 > 全局
AGENTS.md ~/.pi/agent/AGENTS.md + 从 cwd 向上遍历到根 全局 + 祖先链
Skills ~/.pi/agent/skills/ + ~/.agents/skills/ + .pi/skills/ + .agents/skills/ + 包管理 按路径
Extensions ~/.pi/agent/extensions/ + .pi/extensions/ + 包管理 按路径
Prompt Templates ~/.pi/agent/prompts/ + .pi/prompts/ + 包管理 按路径
Themes ~/.pi/agent/themes/ + .pi/themes/ + 包管理 按路径

4.1 AGENTS.md 的加载顺序

// resource-loader.js - loadProjectContextFiles()
export function loadProjectContextFiles(options) {
  const contextFiles = [];

  // 1. 全局 AGENTS.md
  const globalContext = loadContextFileFromDir(resolvedAgentDir);
  if (globalContext) contextFiles.push(globalContext);

  // 2. 从 cwd 向上遍历，收集所有祖先目录的 AGENTS.md
  let currentDir = resolvedCwd;
  while (true) {
    const contextFile = loadContextFileFromDir(currentDir);
    if (contextFile && !seenPaths.has(contextFile.path)) {
      ancestorContextFiles.unshift(contextFile);  // 祖先在前
    }
    const parentDir = dirname(currentDir);
    if (parentDir === currentDir) break;
    currentDir = parentDir;
  }
  contextFiles.push(...ancestorContextFiles);

  return contextFiles;
}

【clerimia：】 最终顺序是：全局 AGENTS.md → 根目录 → … → 当前目录。在 system prompt 中，它们被包裹在 <project_context> → <project_instructions> 里。

5. Extension 的干预点

Extension 可以在三个时机修改 context：

init → _buildRuntime → _rebuildSystemPrompt
                         ↑
                    extension 注册的工具注入 promptSnippet / promptGuidelines

prompt() 调用时：
  ├── before_agent_start 事件
  │   ├── 注入 custom messages（独立于 system prompt）
  │   └── 覆盖 systemPrompt（仅当轮有效）
  │
  └── Agent.prepareNextTurnWithContext（每轮 turn 前）
      └── 取 this._systemPromptOverride ?? this._baseSystemPrompt

5.1 _installAgentNextTurnRefresh：每轮 turn 前的刷新

_installAgentNextTurnRefresh() {
  this.agent.prepareNextTurnWithContext = async (turn, signal) => {
    return {
      context: {
        systemPrompt: this._systemPromptOverride ?? this._baseSystemPrompt,
        tools: this.agent.state.tools.slice(),
      },
      model: this.agent.state.model,
      thinkingLevel: this.agent.state.thinkingLevel,
    };
  };
}

【clerimia：】 这就是为什么 system prompt 可以在运行时被 extension 覆盖，但每轮 turn 结束后又自动 reset 回 _baseSystemPrompt。_systemPromptOverride 是每轮临时变量，_baseSystemPrompt 是持久基线。

5.2 resources_discover 事件：动态追加资源

async extendResourcesFromExtensions(reason) {
  if (!this._extensionRunner.hasHandlers("resources_discover")) return;

  const { skillPaths, promptPaths, themePaths } =
    await this._extensionRunner.emitResourcesDiscover(this._cwd, reason);

  // 追加到 ResourceLoader，触发 rebuild
  this._resourceLoader.extendResources(extensionPaths);
  this._baseSystemPrompt = this._rebuildSystemPrompt(this.getActiveToolNames());
  this.agent.state.systemPrompt = this._baseSystemPrompt;
}

createAgentSession()
│
├── 1. ResourceLoader.reload()
│   ├── 加载 SYSTEM.md / APPEND_SYSTEM.md
│   ├── 加载 AGENTS.md 链（全局 + 祖先 + 当前）
│   ├── 加载 Skills
│   ├── 加载 Extensions
│   ├── 加载 Prompt Templates
│   └── 加载 Themes
│
├── 2. SessionManager.buildSessionContext()
│   └── 从 JSONL 恢复 messages、model、thinkingLevel
│
├── 3. 创建 Agent 实例（systemPrompt = ""）
│
├── 4. 恢复历史 messages → agent.state.messages
│
├── 5. new AgentSession()
│   ├── _installAgentNextTurnRefresh()  ← 安装每轮刷新钩子
│   └── _buildRuntime()
│       ├── 创建内置工具定义
│       ├── 创建 ExtensionRunner
│       └── _refreshToolRegistry()

│   └── _applyExtensionBindings()

│
└── 7. 返回 { session, extensionsResult, modelFallbackMessage }

7. 一句话记忆

Session = (systemPrompt, basePrompt, tools, messages, model, thinkingLevel)
basePrompt 是静态模板的产物，systemPrompt 是 basePrompt 的每轮可变投影。
messages 独立演化，不进入 systemPrompt。
tools 同时存在于 systemPrompt（文本描述）和 Agent state（function schema）。
