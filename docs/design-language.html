为什么这样分配

各自有表达，也有明确边界。

若叶睦：轻盈而有方向

画布近白，文字偏深灰绿；苔绿给主要链接、选中态与焦点提供明确方向，薄荷只用于局部的柔和反馈。

不要：整页铺绿，或让浅薄荷承载关键正文。

墨提斯：鲜活且有张力

鲜绿承担主要行动；酒红承载精选、主题细节与个人表达。它们共享舞台，但无需让所有内容同时高亮。

不要：将酒红默认等同危险，或让颜色削弱文章阅读。

02 · FOUNDATIONS / TYPOGRAPHY

字体与字号系统

共用一套排版，让两个主题保持同一阅读节奏。以下是未来系统的明确提案，字号及行高需用真实内容验证。

字体 · 按职责分工

优先使用项目已具备的字体，避免为规范增加不必要的下载。

clerimia · 标题

标题 / 品牌：Satoshi，中文回退 Microsoft YaHei、system-ui；600–700。中英文可分别调整字距。

不要：对中文标题统一施加负字距。

写下，慢慢思考。

正文 / 界面：Satoshi + 中文系统回退；正文 400，强调 600。中文默认正常字距。

不要：用低对比或极细字重换取“安静”。

2026.10 / code

代码 / 时间：ui-monospace、Consolas、monospace；长代码单独控制行高与横向滚动。

不要：用等宽字体排整段中文正文。

层级如何建立

一个区块优先使用标题、正文与元信息三种角色，利用留白、字重和对齐形成关系。需要强调时先调整层级，再考虑绿色。

何时调整

如果长标题换行不自然，优先调整容器和字号，而不是压缩中文字符；正式固化前对比 390px 与宽屏的真实文本。

03 · FOUNDATIONS / SPACE & COMPONENTS

间距、圆角、尺寸、图标

共同的尺度保持两套主题在结构和使用体验上的一致。数值均为未来系统提案。

4px 基础节奏；间距表达关系，不要求所有场景套同一个值。

关系优先

同一组内使用较小间距，不同内容组使用更大间距；长文段落按阅读节奏安排。

建议起点：组件内部 24px；手机左右 20px；重要区块间 72px，手机 40px。遇到长文或复杂布局时根据真实内容调整。

不要：用固定值把不同信息关系压成同一种节奏。

图标、表面与动效

使用一致的图标语言，动效只为交互和主题表达服务。

图标 · 16 / 18 / 20px

16px 用于行内；18px 为常规控件；20px 用于突出控件。默认线性风格，视觉线宽约 1.75–2px；优先复用项目图标集。

不要：图标按钮缺少可访问名称，或仅靠图标传达复杂状态。

表面与动效

普通内容保持平面；对话框、弹出菜单等可使用阴影。Hover / 颜色反馈 160ms，弹层进入 200ms，主题切换约 220ms，均为提案。

夜间可用酒红与绿色表现主题反馈；正文静止。尊重减少动态偏好，关闭非必要过渡并保留状态变化。

页面框架与验证

主题共享布局，优先真实内容与使用体验。

页面与阅读宽度

站点最大宽度 1080px · 阅读列约 680–760px

站点宽度为布局提案；文章正文应单独限制行长。手机两侧 20px 起；内容较宽时自然收缩。

验收方法

分别检查首页、文章列表、文章详情：宽屏与 390px、若叶睦与墨提斯两主题。验证长标题、中文混排、链接、焦点、触控区域与减少动态效果。

保留截图和实际对比度结果；未验证的提案不等于已经通过验收。
