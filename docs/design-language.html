为什么这样分配

各自有表达，也有明确边界。

若叶睦：轻盈而有方向

画布近白，文字偏深灰绿；苔绿给主要链接、选中态、焦点和身份提供明确方向，薄荷只用于局部的柔和反馈。

不要：整页铺绿，或让浅薄荷承载关键正文。

墨提斯：鲜活且有张力

鲜绿承担主要行动；酒红分作两用——跨主题的身份（提示符用户名、头像框、终端标题栏）与只在夜间出现的主题细节（主题开关、每日一句顶线）。两者共享舞台，但无需让所有内容同时高亮。

不要：将酒红默认等同危险，或让颜色削弱文章阅读。

关系优先

同一组内使用较小间距，不同内容组使用更大间距；长文段落按阅读节奏安排。

建议起点：组件内部 24px；手机左右 20px；重要区块间 72px，手机 40px。遇到长文或复杂布局时根据真实内容调整。

不要：用固定值把不同信息关系压成同一种节奏。

04 页面框架与断点

从手机的单列阅读与触屏操作出发，随空间增加再安排内容；宽屏先保护阅读宽度，再决定目录能否并列。

≤ 680px · 紧凑 两侧 20px

单列；简介与头像上下排列。导航优先全部可见或换行，目录通过入口打开。

> 680 且 < 1000px · 过渡 两侧 24px

单列阅读；目录收进入口，列表的辅助信息移到主内容之后。

≥ 1000px · 宽屏 两侧 32px

内容容器达到 936px 才并列；没有目录就不预留空栏。

手机先行：两侧各 20px 时，320 / 390 / 430px 的可用宽度分别约为 280 / 350 / 390px（未扣除安全区与滚动条）。正文以 16px / 1.8 为起点，目录收进可关闭的入口；触控目标优先达到 44 × 44 CSS px。

为什么是 680px？先沿用项目现有的紧凑布局切换点，是待验证的初稿，不是手机型号的分界线。导航可自行换行，标题和头像尺寸平滑变化，避免尺寸在断点处突变。

为什么是 1000px？估算：宽屏阅读列目标 680 + 列间 32 + 目录 224 + 两侧各 32 = 1000。实际还要求内容容器至少 936px；滚动条、安全区等占用空间时，放不下就保持单列。这里的 680 是阅读列目标，并非手机正文最小宽度。

如何验证：检查 320–430px、断点两侧、横屏与 200% 缩放。长标题应换行，代码和表格只在自身区域滚动；导航若横向滚动，要提示还有内容并支持键盘操作。浏览器模拟不能代替真实设备验证。

终端 · 已重做为 macOS 风格壳子，实际设备待验证

反馈强度匹配状态稀有度：终端输入行是常驻状态，不套整圈焦点环；聚焦由壳子外边框和输入行顶部 1px 边线变为操作色（160ms）表达，块状光标承担「可以打字」的主要信号。光标只在聚焦且无选区时闪烁，有选区时交还系统选区；减少动态效果时常亮。帮助表命令列固定宽度对齐，窄屏改为两行。终端画布与边线用独立 --term-* token，不混用文章卡片 token。标题栏是身份牌，取 --color-identity-surface / -edge / -ink；提示符里的用户名取 --color-identity，日间苔绿、夜间酒红，❯ 保持行动色。

首次打开时 banner 说明怎么开始，下面给一行「试试 help · ls · whoami」，命令字可点击执行，不认命令的人也能先看到结果。终端是模态对话框，关闭状态必须真正隐藏，不能以任何形式留在页面流里。入口两处：页头 >_ 图标是全站常驻快捷键；首页 hero 动作行在「阅读文章 / 翻翻笔记」之后放次级文字入口「在终端里逛逛」，因为首访者落在首屏，图标和 title 只在悬停时可读。

减少动态效果：响应 prefers-reduced-motion，关闭非必要过渡、位移、闪烁和平滑滚动；内容、状态、焦点与关闭方式仍完整保留。 终端光标只在输入焦点内闪烁，阅读区域不持续运动。

实施与验证：页框、导航换行、平滑字号和基于容器宽度的目录与列表侧栏已接入。模拟检查了日夜主题、320–1440px 的代表宽度和目录键盘操作；真实设备、安全区及缩放仍待验证。文章行方向箭头已共享，浏览器已检查悬停、键盘焦点和减少动态效果，实际设备待验证；目录进入使用 220ms，其余动效尚未统一，部分页面仍有 300ms 入场。详见 文字规范的差距清单。
