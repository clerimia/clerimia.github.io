为什么这样分配

各自有表达，也有明确边界。

若叶睦：轻盈而有方向

画布近白，文字偏深灰绿；身份与行动分别命名，当前都使用苔绿。薄荷只用于局部的柔和反馈。

不要：整页铺绿，或让浅薄荷承载关键正文。

墨提斯：鲜活且有张力

绿色延续同一个人的身份（品牌、首页名字与提示符用户名）；双头像由人物提供身份线索，圆形图片保留细边线，首页另有身份绿轨道。酒红回应行动（主要链接与合适的交互状态）。每日一言回归中性或身份绿，主题开关只在操作时反馈。

不要：将酒红等同危险，因「表达」给非行动内容染红，或用深酒红直接绘制深底小字。文章图示保留服务内容的分类色，键盘焦点使用独立焦点色。

关系优先

同一组内使用较小间距，不同内容组使用更大间距；长文段落按阅读节奏安排。

建议起点：组件内部 24px；手机左右 20px；重要区块间 72px，手机 40px。遇到长文或复杂布局时根据真实内容调整。

不要：用固定值把不同信息关系压成同一种节奏。

图标 · 16 / 18 / 20px

16px 用于行内；18px 为常规控件；20px 用于突出控件。默认线性风格，视觉线宽约 1.75–2px；优先复用项目图标集。

表面与层级

详细文章列表用单列表面与边线区隔，卡内通过字号、颜色与间距建立层级；首页与归档简行保持平面。

让布局安定，让回应自然。

两种主题共享页面框架和交互节奏。布局为阅读留出空间，动效只在状态变化时提供清楚的回应。

页面框架

04 页面框架与断点

从手机的单列阅读与触屏操作出发，随空间增加再安排内容；宽屏先保护阅读宽度，再决定目录能否并列。

≤ 680px · 紧凑 两侧 20px

单列；简介与头像上下排列。完整品牌与工具保持一行，栏目与搜索进入菜单，目录通过入口打开。

> 680 且 < 1000px · 过渡 两侧 24px

单列阅读；目录收进入口，列表辅助信息移到主内容之后。页头 ≤760px 使用菜单，更宽时显示整行栏目。

≥ 1000px · 宽屏 两侧 32px

内容容器达到 936px 才并列；没有目录就不预留空栏。

返回与页头：About、Links、列表和内容页的返回入口、页头与页框共用左基线，入口到底下的正文保持 24px。阅读列限宽时靠左；标题前如有文章日期、标签或封面，保留内容自己的层级。已通过 BaseLayout / ContentLayout 的 back 与 .site-page-main 接入，例外应记录理由与验证方式。

手机先行：两侧各 20px 时，320 / 390 / 430px 的可用宽度分别约为 280 / 350 / 390px（未扣除安全区与滚动条）。正文以 16px / 1.8 为起点，目录收进可关闭的入口；触控目标优先达到 44 × 44 CSS px。

为什么是 680px？保留为页框边距和首页布局规则；页头独立采用 760px 内容断点，窄屏从顶部就折叠栏目与搜索，滚动不改变导航结构。

页头：页头随页面正常滚动，不吸附视口。保持新版横向绿色 logo、终端、主题和菜单的顺序；tagline 在首页 hero 展示，不重复放在页头。logo 使用日夜主题的身份色（已实现，待宽屏与手机验证）。桌面 / 移动高 72 / 64px；页头与内容共用页框宽度和左右基线。

工具与菜单：工具命中区域 44×44px，通过内部 4px 留白形成 36px 的细边框。桌面搜索、终端与主题开关同属一个右侧工具组，容器间距 4px，按钮边框间可见约 12px；移动端搜索留在导航菜单，顶部保留终端、主题和菜单。移动菜单在页头下方 8px 纵向、右对齐展开，栏目与搜索行至少 48px，当前栏目只用字重并保留 aria-current；面板可内部滚动。关闭时立即 inert 并播放退出动画，支持键盘、Escape、外部点击、离开焦点关闭及焦点恢复。

目录入口：单列布局在视口右下角安全区竖排目录与返回顶部按钮，目录在下；两者触控区域至少 44×44px、间距 8px，离视口边缘至少 20px。宽屏目录并列时隐藏浮动入口。抽屉不显示关闭按钮，可通过遮罩、Escape 或选择目录项关闭；打开时聚焦首个目录项，关闭后焦点回到入口。进出均使用 220ms、至多 8px 位移。正文锚点保留 24px 顶部阅读间距。

目录状态：当前项以行动色文字和左侧竖线标记阅读位置；指针悬停只改变文字颜色，日间使用 --primary-active，夜间使用 --primary-hover，当前项悬停时竖线保持不变。键盘焦点使用独立焦点环，触屏不依赖悬停反馈。

为什么是 1000px？估算：宽屏阅读列目标 680 + 列间 32 + 目录 224 + 两侧各 32 = 1000。实际还要求内容容器至少 936px；滚动条、安全区等占用空间时，放不下就保持单列。这里的 680 是阅读列目标，并非手机正文最小宽度。

如何验证：检查 320–430px、断点两侧、横屏与 200% 缩放。长标题应换行，代码和表格只在自身区域滚动；导航若横向滚动，要提示还有内容并支持键盘操作。浏览器模拟不能代替真实设备验证。

菜单与目录：菜单通过展开高度、透明度及至多 6px 位移双向过渡，目录进出均为 220ms、至多 8px。正文、内容页头和侧栏保持稳定。

文章行方向箭头

整行文章链接的辅助方向提示：默认显示右尖括号，悬停或键盘聚焦时箭头尖向右移动，横线同步长出。图标变形 220ms、颜色 160ms，均为 ease-out；触屏不依赖悬停，减少动态效果时立即切换。外部链接、分页与正文图示各自处理。

终端

宽屏且非粗指针时打开终端直接聚焦输入框；680px 以下或粗指针先聚焦关闭按钮，避免软键盘立即盖住帮助内容，点击命令或输入行后可输入。关闭按钮保持圆点外观，实际目标 44×44px，不放在 aria-hidden 容器内。反馈强度匹配状态稀有度：终端输入行是常驻状态，不套整圈焦点环；聚焦由壳子外边框和输入行顶部 1px 边线变为操作色（160ms）表达，块状光标承担「可以打字」的主要信号。光标只在聚焦且无选区时闪烁，有选区时交还系统选区；减少动态效果时常亮。帮助表命令列固定宽度对齐，窄屏改为两行。终端画布与边线用独立 --term-* token，不混用文章卡片 token。标题栏是身份牌，取 --term-chrome / --term-chrome-edge / --term-foreground；提示符用户名两主题都取绿色 hsl(var(--brand))，❯ 使用行动色。

首次打开时 banner 说明怎么开始，下面给一行「试试 help · ls · whoami」，命令字可点击执行；动态生成的按钮通过事件委托处理，不认命令的人也能先看到结果。终端是模态对话框，关闭状态必须真正隐藏，不能以任何形式留在页面流里。入口两处：页头 >_ 图标是全站常驻快捷键；首页 hero 动作行在「阅读文章 / 翻翻笔记」之后放次级文字入口「在终端里逛逛」，因为首访者落在首屏，图标和 title 只在悬停时可读。

减少动态效果：过渡时长和延迟真正归零，避免统一赋值 0.01ms 让子元素对继承的 visibility 产生短暂过渡、阻挡即时聚焦。响应 prefers-reduced-motion，关闭非必要过渡、位移、闪烁和平滑滚动；内容、状态、焦点与关闭方式仍完整保留。 终端光标只在输入焦点内闪烁，阅读区域不持续运动。首页例外（已实现，待浏览器与设备验证）：问候、两行标语、简介、入口及头像短暂错时浮入，句号轻微呼吸；键盘进入操作时立即显示对应区域。枝叶生长一次、落叶飘落一次，头像外轨道及小点以 40 秒缓慢旋转；入口与社交图标悬停轻微上移。减少动态效果时内容立即呈现、枝叶与轨道静止且悬停不移动。检查宽屏、390px、日夜主题、减少动态效果、键盘焦点及返回首页的表现。

首页首屏构图（已实现，待验证）：宽屏接近一屏的双栏，左侧大标语与入口、右侧头像，左下枝叶配淡绿色局部光晕；手机纵向排列。标语宽屏 48–80px、手机 34–48px，以两行及从身份绿过渡到正文色的渐变突出「一边」；标题局部使用原型的 Noto Sans SC 900（自托管标题字集），渐变为 100deg、身份绿 30% 至正文色 130%；逗号和句号保留可选择、可复制的中文字符，由字体呈现圆润造型并使用柔和身份绿。（已实现；宽屏、390px 与日夜主题下已检查字体加载、标题选择文本及无横向溢出，真实设备待验证）阅读文章为实心行动色链接，翻翻笔记为描边链接，终端为次级文字按钮。验证两种宽度与主题下的可读性、交互、位置和文章入口。

搜索、折叠与条目

搜索页面级结果使用转义后的完整 description，段落结果保留匹配片段；日期、时长、语言和标签不进入正文摘要。筛选标签使用明确的数据值，避免断句符号进入筛选值。未选中的零结果项隐藏，已选中项归零时保留以便取消。筛选标题、筛选标签及短标签链接至少 44×44px，相邻目标不重叠。

Links 折叠区采用原生 details / summary，向下 / 向上的符号表达状态，以辅助色到行动色反馈操作，不复用跳转箭头或下划线。推荐描述允许完整换行。Notes 列表标题使用 18px / 600 的条目层级，详情目录保持目录层级。
