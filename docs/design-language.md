# clerimia 前端设计系统

本文件是设计系统的**文字规范**：定义色彩、排版、尺度、组件和验证方法，供设计与实现查阅。[可视化规范](design-language.html) 展示同一套规则及样例，两者应保持一致。[DESIGN.md](../DESIGN.md) 记录灵感和大方向，[AGENTS.md](../AGENTS.md) 是仓库入口与工作约定。

**状态：部分落地，持续验证。** 两套主题的基础色、排版和尺度 token 已写入 `src/assets/styles/app.css`；首页、文章列表与文章详情已按本规范调整。其他页面、第三方组件与各类交互状态尚未全部验收。数值仍是可根据真实内容调整的初稿，不以代码存在等同于全面验证。规则调整时同步更新本文与 HTML。设计意图来自 [博客设计思路](https://app.notion.com/p/40540f8bc1e6804ab903fa51c4225aae)、[设计取舍](https://app.notion.com/p/40540f8bc1e681a39bfdd40e8c0beaf5) 和用户补充的墨提斯主题气质。

## 理念与主题

**安静，但有自己的声音；整体安静，局部鲜活。** 文章、项目和持续变化的思考是主体。绿色和双头像是个人识别，互动细节表达情绪；不以大量装饰证明个性。

- **若叶睦（日间）**：安静、轻盈、柔和。近白画布、深灰绿文字、低饱和苔绿和薄荷局部表面。
- **墨提斯（夜间）**：开放、活力、戏剧性。炭灰画布保持阅读安静；绿色延续共同身份，酒红回应主要行动和适合的交互反馈。

两种角色是同一个人的不同面向，彼此共存并走向融合：身份因此保持绿色，而行动可以用各自的声音。两套主题共享内容结构、布局、排版和组件交互；酒红不是错误色，也不是所有「表达」内容的装饰。主题差异不应改变阅读顺序和操作习惯。

| `--term-muted` | `#536a5b` | `#93a89a` | 终端内的辅助文字 |

身份与行动分别命名，即使日间当前使用同一绿色也不将两种语义绑在一起。夜间首页名字、品牌标记和终端身份牌保持绿色；双头像以人物本身提供身份线索，圆形图片只用一条细边线，不再套静态色块。每日一言的分隔线回归中性，引号使用身份绿；主题开关默认和其他图标按钮一致，仅在交互时使用行动反馈。正文链接有下划线，普通导航与次级入口保持较低权重。文章图示的分类色仍属于内容语义，不因操作色变化而自动变红；图内键盘焦点使用独立焦点色。原 `--color-expression*` 已移除，不再以宽泛的「表达」决定酒红落点。

成功、警告与错误分别有状态 token；终端成功结果通过文字或箭头说明操作与目标，例如 `theme → dark`。焦点独立于行动色。终端的红黄绿圆点沿用 macOS 系统色（`#ff5f57` / `#febc2e` / `#28c840`），属于外来窗口语言，不参与本站语义色板。astro-pure / UnoCSS 的 `--primary`、`--primary-foreground` 分别映射行动色与行动文字，`--ring` 映射焦点；旧 `--leaf` 别名仍指向行动色，身份组件直接使用 `--color-brand`。

纯色计算（日 / 夜）：正文对画布 11.63:1 / 14.82:1；辅助文字 5.68:1 / 8.76:1；行动色对画布 5.57:1 / 7.59:1、对一般表面 5.76:1 / 6.29:1、对行动弱表面 5.03:1 / 6.50:1。悬停与按下色对行动弱表面分别为 6.87 / 8.14:1（日）和 9.49 / 7.27:1（夜）；实心文字对默认、悬停、按下行动底分别为 5.76 / 7.87 / 9.34:1（日）和 7.42 / 10.84 / 8.30:1（夜）。身份牌文字对身份表面为 12.02:1 / 8.21:1；焦点色对画布为 7.62:1 / 10.67:1，对行动弱表面为 6.87:1 / 9.13:1。终端的警告和错误文字对表面分别为日间 6.57 / 6.64:1，夜间 8.25 / 7.74:1。

以上是纯色计算，不覆盖透明度、图片或所有第三方状态。普通文本以 4.5:1、必要控件边界与状态以 3:1 为目标；需要更强的控件边界时针对实际表面另行设计。状态需辅以文字或图标，不能只靠颜色区分。色值与酒红使用频率仍需在真实内容、设备和第三方组件中持续验证。

## 02 字体与字号

字体：Satoshi 配 Microsoft YaHei、system-ui 回退；代码与终端用 ui-monospace、Consolas、monospace。中文标题从正常字距开始，英文品牌字标可独立微调。正文用 400，标题及重点以 600–700 为起点；不要通过降低正文对比度表达安静。

| 角色 / token | 宽屏字号 / 行高 | 窄屏起点 / 行高 | 主要用途 |
| --- | --- | --- | --- |
| Display `--font-display` | 48 / 1.2 | 34 / 1.2 | 首页主标题 |
| Page title `--font-page-title` | 36 / 1.25 | 28 / 1.3 | 文章和页面标题 |
| Section `--font-section` | 24 / 1.35 | 22 / 1.35 | 区块标题 |
| Item title `--font-item-title` | 18 / 1.45 | 18 / 1.45 | 文章条目标题 |
| Lead `--font-lead` | 18 / 1.75 | 17 / 1.75 | 简介、引言 |
| Reading `--font-reading` | 16 / 1.8 | 16 / 1.8 | 长文正文 |
| UI `--font-ui` | 14 / 1.6 | 14 / 1.6 | 导航、按钮、短摘要 |
| Meta `--font-meta` | 12 / 1.5 | 12 / 1.5 | 日期与辅助信息 |

Display、Page title、Section 和 Lead 的字号在表中两端之间随视口平滑变化，避免在 680px 两侧突然跳变；表中的窄屏值是下限而不是整个手机区间的固定值。宽屏文章列先比较 680–760px 与真实中英文行长，手机正文随可用宽度收缩；12px 仅用于少量非关键元信息。按内容检查字号、换行、字重与间距，不因为字号表存在就机械套用。

## 03 间距、圆角、尺寸、图标

- **间距**：`--space-1/2/3/4/5/6/8/12/18` 分别为 4/8/12/16/20/24/32/48/72px。同组间距小于组间距；手机页面两侧 20px、大区块间 40px 可作为起点。
- **圆角**：代码 6px、控件 10px、面板 16px、对话框 24px、胶囊 999px；文章行优先无外框。圆角依据职责，而非所有内容都成卡片。
- **控件高度**：32px 密集控件、44px 默认、52px 突出入口；交互目标优先至少 44×44 CSS px。小型视觉控件应扩大命中区域并避免互相重叠。
- **图标**：16px 行内、18px 默认、20px 突出控件；线性风格，视觉线宽约 1.75–2px，优先复用现有图标集。图标按钮有可访问名称与可见焦点。
- **表面**：常规内容平面；对话框等浮层可用阴影。页面框架与动效的具体设计见下文。

## 04 页面框架与断点

**状态：基础框架已接入，数值仍需继续验证。** 从手机的单列阅读和触屏操作出发，随可用空间增加再安排更多内容；若叶睦和墨提斯共享同一个框架，让主题切换不改变阅读顺序。宽屏优先保证文章行长，再决定是否放下目录；侧栏不是每个页面的必需品。

### 页面框架

| 职责 | 设计值 | 使用与边界 |
| --- | --- | --- |
| 站点页框 | 最大 `1080px`（`--layout-wide`） | 容纳导航和页面内容，始终在视口内居中；页面外边距随下表变化 |
| 阅读列 | 最大 `760px`（`--layout-reading`） | 文章正文、长段文字；空间不足时随页框收缩，不强制固定宽度 |
| 文章目录 | 宽屏 `224px`（`--layout-aside`），与正文间距 `32px`（`--space-8`） | 仅在存在目录且宽度足够时并列；不以压窄正文来容纳侧栏 |

页框先扣除两侧外边距，正文与导航使用共同的左对齐基线；不要在页框内再叠加没有职责的固定横向内缩。宽屏文章布局最多占 `760 + 32 + 224 = 1016px`；页框更宽时剩余空间自然留白。没有目录的文章不预留空侧栏，列表仍以内容行组织，只有确有独立内容的项目才使用卡片。

**返回入口与页头：已接入 About、Links、列表和内容页。** 返回入口、页头和页框使用同一左基线；返回入口到底下的 `<main>` 保持 `24px`（`--space-6`），宽屏和窄屏一致。阅读列即使不足页框宽度也靠左，剩余空间留在右侧。标题是页头首项时不另加顶部间距；文章可以在标题前放日期、标签或封面，它们内部的顺序与间距按内容职责处理。

实现时，直接使用 `BaseLayout` 的 `back` 参数，或内容页的 `ContentLayout` 的 `back` 参数，并让 `<main>` 使用 `.site-page-main`；单列长文复用 `.reading-column`。这让返回控件和间距有共同来源，而 About 可保留个人介绍、头像及自己的内容顺序。新页面若确需偏离，记录场景、理由和验证方式；修改页框时运行 `tests/page-frame.test.mjs` 并在浏览器用 `tests/page-frame.browser.mjs` 比较代表页面、宽度和主题。

### 响应式规则

| 视口宽度 | 页框两侧外边距 | 内容与导航 |
| --- | --- | --- |
| `≤ 680px` | `20px` | 单列；首页简介与头像上下排列。栏目与搜索进入菜单，完整品牌与工具保持一行；文章目录用可关闭的入口打开。 |
| `> 680px 且 < 1000px` | `24px` | 单列阅读，正文不超过 `760px`；文章目录收进入口，列表辅助信息移至主内容之后。页头 `≤ 760px` 使用菜单，更宽时显示整行栏目，不压小文字。 |
| `≥ 1000px` | `32px` | 页框最大 `1080px`；实际内容宽度达到 `936px` 时，有目录的文章可用正文 + `32px` 间距 + `224px` 目录。放不下时仍用单列。其他页面根据内容决定列数，不为了填满页框而加卡片。 |

两侧 `20 / 24 / 32px` 分别复用 `--space-5 / --space-6 / --space-8`。这些宽度以 **CSS 像素**计量，不把物理分辨率或设备名称当作断点依据：手机横屏、分屏和浏览器缩放后同样根据实际可用空间适配。

**断点的由来与限制：**

- `680px` 保留为页框边距、首页介绍等紧凑布局的**初稿**，并非依据手机型号推导。页头独立采用下述内容断点，不再在 `680px` 强制导航换行。各组件应在内容真正放不下时调整；它们不必强行在同一宽度变化。
- `1000px` 是文章目录并列的**理想条件估算**：`680px` 的宽屏阅读列目标 + `32px` 间距 + `224px` 目录 + 两侧各 `32px` 外边距。这里的 `680px` 是并列时的阅读列目标，与上面的视口断点只是数值相同；它不是手机正文的最小宽度。实现同时要求视口至少 `1000px` 且内容容器至少 `936px`：滚动条、安全区或其他内缩会减少可用空间，放不下就保持单列。例如当前桌面模拟浏览器的滚动条占 `6px`，实际到 `1006px` 视口才满足并列条件。修改阅读列下限、目录宽度或列间距时，应同步调整容器查询。两者均需用真实内容和设备继续验证。

### 手机优先检查

- **正文**：从 `320px` 可用宽度开始支持单列；两侧各 `20px` 时，`320 / 390 / 430px` 可分别留出约 `280 / 350 / 390px` 的内容宽度（未扣除安全区和滚动条）。正文以 `16px / 1.8` 为起点，宽度跟随容器，不设宽屏阅读列的最小宽度。
- **导航与操作**：完整品牌、终端、主题与菜单保持一行，栏目和搜索通过菜单可达，不靠缩小字号塞进一行。触控目标优先至少 `44 × 44 CSS px`，避免相邻目标重叠。文章目录在单列时通过独立的右下角浮动按钮打开，与全站栏目导航保持分开。
- **内容与安全区**：长标题和链接允许换行，图片限制在容器内；代码与表格在自身区域横向滚动，页面本身不横向溢出。页面边距应避开设备安全区，浮动按钮不能遮住正文或底部操作。
- **验证矩阵**：至少检查 `320 / 360 / 375 / 390 / 414 / 430px`、断点两侧和较宽视口下 `200%` 缩放；加看手机横屏与有安全区的设备。用真实首页、列表和长文章，在日夜主题下检查导航可发现性、目录、换行、触屏、键盘焦点与局部横向滚动。浏览器模拟只能初筛，不能替代真实设备和内容验证。

### 悬浮页头与目录入口（2026-10-28 修订）

**状态：用户已确认 Joye Blog 四种状态的参考方向；本地实现，浏览器与真实设备验证分别记录。** 响应式规则与滚动规则各自承担一个职责：`760px` 以下从页面顶部就把栏目与搜索收进菜单；滚动只改变同一页头容器的尺寸、内缩与表面。完整的绿色 `c. clerimia` 字标、终端、主题和菜单在窄屏始终保持顺序。标语在 `1100px` 及以上显示，较窄时为导航留出空间。

- **默认状态**：桌面页头 `72px`，移动页头 `64px`，流内占位固定；宽屏栏目、搜索直接可见，窄屏菜单从顶部即可操作，不在滚动时更换导航结构。
- **阅读状态**：向下超过 `32px` 时形成悬浮栏，回到 `8px` 以内恢复。悬浮栏在安全区下方至少留 `12px`，桌面高 `60px`，移动高 `56px`。宽屏左右内缩 `clamp(12px, 4vw, 48px)` 并加 `12px` 内边距；移动端保持页框两侧外边距，栏内留 `8px`。字标字号、工具顺序和布局模型保持稳定，正文位置不跟随改变。
- **视觉职责**：工具按钮命中区域 `44×44px`，细边框通过内部 `4px` 留白形成 `36px` 视觉外框。桌面搜索、终端与主题开关同属一个右侧工具组，组内容器间距 `4px`，按钮边框间可见约 `12px`；移动端搜索留在导航菜单，顶部保留终端、主题和菜单。悬浮栏沿用画布、边线和 `16px` 面板圆角，只有浮于正文之上时用轻阴影标明层次，不增加新的配色或渐变。
- **移动菜单**：在页头下方 `8px` 展开，纵向、右对齐，栏目与搜索行至少 `48px`；当前栏目只用字重表达，同时保留 `aria-current`。面板有最大可用高度并在内部滚动。关闭时立即 `inert`，保留退出动画；支持 Enter / Space、Tab、Shift+Tab、Escape、外部点击、焦点离开关闭与焦点恢复。普通导航不采用应用菜单角色。跨过滚动阈值或软键盘改变视口高度时，不主动关闭菜单。

## 05 动效与交互

**状态：部分接入。** 页头、移动导航、目录的进入和退出与文章行方向箭头已接入；普通阅读内容立即呈现，取消正文、页头与侧栏的错时上浮，其余第三方浮层继续逐步对照。动效让操作有回应，让浮层的出现和消失有方向；文章与思考本身保持稳定。两种主题使用相同时间、位移和操作方式；夜间酒红用于适合的行动反馈，不增加整页闪烁或持续运动。

| 提议 token | 时长 / 曲线 | 使用 | 不使用 |
| --- | --- | --- | --- |
| `--motion-header` | `300ms`，复用 overlay 曲线 | 页头高度、横向收拢、内边距；表面使用 160ms | 不切换布局模型、不缩放文字、不替换品牌与工具 |
| `--motion-feedback` / `--motion-feedback-easing` | `160ms`，`ease-out` | 指针悬停、选中等颜色或边框反馈 | 键盘焦点不得延迟；触屏不依赖 hover |
| `--motion-overlay` | `220ms`，`cubic-bezier(0.2, 0, 0, 1)` | 对话框、目录进入与退出；透明度配合至多 `8px` 的位移 | 不让页面正文跟随移动，也不以动效推迟状态更新或焦点进入 |
| `--motion-theme` | `240ms`，`ease-out` | 主题开关、头像附近等小范围的主题反馈 | 正文前景和画布同步切换，不对整页做淡入淡出；避免切换中出现低对比度 |

点击状态以颜色或边框回应，默认不缩放、不移动文字；焦点环立即出现。目录跳转可使用浏览器原生平滑滚动，启用减少动态效果时立即跳转。页面切换和正文首屏默认直接呈现，不做逐段错时入场；终端光标仅在输入焦点内闪烁，首页静态阅读区不持续闪烁。

主题切换时暂时停止元素的颜色过渡，让画布与文字同步更新；完成绘制后恢复普通交互过渡。页头开关、终端命令与已保存主题同步采用同一处理。

启用 `prefers-reduced-motion: reduce` 时，过渡时长与延迟真正归零，避免统一赋值 `0.01ms` 让本无过渡的子元素也对继承的 visibility 生成短暂过渡、造成可见但不可聚焦；取消非必要的过渡、位移、闪烁和平滑滚动；状态、内容、焦点和关闭方式仍完整保留。只过渡所需的属性，不使用 `transition: all`。键盘打开浮层时立即设置名称与展开状态、将焦点送入；关闭后恢复焦点，Escape 和触屏操作保持可用。

### 终端输入行

**状态：已用于站点终端弹窗；浏览器已检查日夜主题、390px 窄屏、长文本横向滚动、选区、帮助表对齐与减少动态效果，标题栏与用户名的身份色在两套主题下核对过，实际设备待验证。**

反馈强度应匹配状态的稀有程度。宽屏且非粗指针时打开终端直接聚焦输入框；`680px` 以下或粗指针环境先聚焦关闭按钮，避免软键盘立即盖住帮助内容，点击命令或输入行后可输入。此策略为本地实现，需真实手机复核。关闭按钮保留圆点外观，实际目标为 `44×44px`，不能放在 `aria-hidden` 容器内。输入框聚焦属于常驻状态，因此**不使用整圈键盘焦点环**：聚焦由壳子外边框与输入行顶部 `1px` 边线由 `--term-edge` 变为 `--color-action`（`160ms`）表达，光标本身承担「可以打字」的主要信号。鼠标点入和键盘 Tab 进入得到同一表达；焦点环保留给按钮、链接等一次性进入的控件。

光标是纯色块，宽 `0.6em`、高 `1.25em`、1px 圆角，取 `hsl(var(--primary))`；只在聚焦且无选区时显示并闪烁 `1.06s steps(2)`，有选区时隐藏、交还给系统选区。原生 `caret-color` 设为透明，位置由与输入框同字号的隐藏镜像按插入点前字宽推算，因此**镜像的字号、字体必须跟随输入框**（窄屏 `14px` 断点同样同步）。原生占位符只在失焦且为空时显示，聚焦后让位给光标。减少动态效果时色块不闪烁、保持常亮。

帮助列表把「命令列」固定为最长命令的宽度（`max-content`），描述列占满剩余，dt 与 dd 之间用 18px 留白；窄屏下改为「命令 / 描述」两行，不强行对齐。终端画布、边线与辅助文字使用独立的 `--term-*` token（职责见色彩表；日间沿用纸面，夜间换成墨提斯的暗绿），不混用文章卡片的 `--card-*`。标题栏是这台终端的身份牌，取 `--color-identity-surface / -edge / -ink`；提示符里的用户名取跨主题的绿色 `--color-identity`，`❯` 使用行动色——它说的是「可以在这里输入」，不是「你是谁」。标题栏用 macOS 风格的红黄绿圆点，其中红色可点、黄绿暂为占位；站点标题与提示居中，右边是 `Esc` 提示。

首次打开时，banner 说明怎么开始，下面再给一行「试试 `help` · `ls` · `whoami`」：命令字用操作色、可点击执行，其余为辅助色；动态生成的按钮通过事件委托处理。这样不认命令的人也能先点一下看到结果，而不是对着空提示符发呆。终端是模态对话框，关闭状态必须真正 `display: none`（author 的 `display` 会覆盖 `dialog:not([open])` 的 UA 规则），不能让它以任何形式留在页面流里。

入口分两处：页头的 `>_` 图标是全站常驻快捷键，保持图标按钮的一致节奏；首页 hero 动作行在「阅读文章 / 翻翻笔记」之后放一个次级文字入口「`>_` 在终端里逛逛」，用辅助色、悬停转操作色。首访者落在首屏、需要被告知这个功能存在，而图标和 `title` 只在悬停时可读，触屏等于没有。
